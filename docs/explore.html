Follow one record

  1. A record starts in a source: here, an order line in the cloud data warehouse.
  2. It lands in raw exactly as it arrived.
  3. It is cleaned: types fixed, duplicates removed, filed under its subject area.
  4. It is joined and defined with the business’s own definitions.
  5. The governed model applies row-level security, so only the right people can see it.
  6. It appears in the executive report.
  7. A leader reads it, and sees only the figures they are meant to.
Text version of this map
  • Sources (where data starts)
    • Cloud data warehouse. A cloud data warehouse that holds finance and client data. Changed: Read from, never changed. The platform adds the layers, the rules and the monitoring around it. Role: Architect and builder of how it is read.
    • On-premises sources. Sources that live on the company network, reached through a data gateway. Changed: Its figures flow into the same governed platform as everything else, instead of staying in a silo. Role: Architect and builder.
    • SharePoint and Dataverse. Lists, forms and business tables that people already work in. Changed: What teams capture by hand becomes data the platform can use, with checks on the way in. Role: Architect and builder.
    • File stores. Files that arrive from partners and teams. Changed: Files land in the platform on a schedule instead of being opened and re-keyed by hand. Role: Architect and builder.
  • Data platform (raw, cleaned, business-ready)
    • Raw. Data lands exactly as it arrives, so there is always a trail back to the source. Changed: Nothing is lost or silently altered. Role: Architect and builder.
    • Cleaned. Types fixed, duplicates and bad rows handled. Organised by subject area: finance, clients, operations and more. Changed: One tidy, consistent version of each subject area. Role: Architect and builder.
    • Business-ready. Joined together and defined with the business’s own definitions, ready for models and apps. Changed: Every report and app starts from the same numbers. Role: Architect and builder.
    • Orchestration pipeline. One pipeline runs the whole chain through the day, with explicit failure rules (what may carry on, what must stop) and an alert at each stage. Changed: Data refreshes through the day and tells you when something breaks. Role: Architect and builder.
  • Serving (what apps and reports read)
    • Semantic models. Governed models with row-level security, so each leader sees their own figures. Changed: One definition of every measure, and the right people see the right rows. Role: Designed and built.
    • SQL database for apps. A SQL database that apps can read and write, built on the same governed data. Changed: Apps get a proper shared record instead of spreadsheets. Role: Designed and built.
    • Natural-language data agents. Ask a question in plain English and get an answer from the governed data. Changed: Leaders can ask their own questions without waiting for a new report. Role: Designed and built; the executive agent is being added.
  • Experiences (what people use)
    • Executive reporting. A governed view of actual, budget, latest estimate and prior-year performance for the C-suite, with each regional leader seeing their own figures. Now adding a natural-language data agent. Changed: One version of the truth for leadership, instead of separate packs. Role: Designed, built and run.
    • Business apps. A SQL database and web app on Fabric to replace manual, spreadsheet-based order tracking: shared editing with an audit log, saved views and dashboards. Changed: One shared, audited record the operations team can work on together. Status: built; rolling out. Role: Designed and built.
    • Automations. Solutions that take manual processes off people’s desks: a finance approval workflow, collecting data from external partners, and read-only health monitors that check every flow and data pipeline every day. Flows are defined in code and compared with what is live before any change. Changed: Processes that ran on email and spreadsheets now run themselves, with an audit trail and early warning. Role: Designed and built them; I own changes to production.
    • Data Q&A desk. A read-only service that answers ad hoc data questions from the governed data, using the business’s own definitions. Every answer is rechecked by a separate agent before it goes out, and arrives as a ready-to-send reply plus a spreadsheet with the data and notes. Changed: Fast, consistent answers without waiting for a new report. Role: Designed and built.
  • People (who it is for)
    • C-suite. The leadership team. Changed: One version of the truth instead of separate packs. Role: I design the reporting around how they actually read it.
    • Regional leaders. Leaders of each region. Changed: They see their own figures, from the same governed source as everyone else. Role: Row-level security designed and built.
    • Operations. The teams who run orders and day-to-day processes. Changed: One shared, audited record to work on together, and fewer manual steps. Role: Apps and automations designed and built for them.
    • Clients. The clients the group serves. Changed: KPI reporting taken from scoping to live service. Role: Client reporting designed and built.
  • How it gets built (the delivery system behind all of the above)
    • Agentic delivery suite. Toolkits for Power BI reports, Fabric apps and Power Platform, each with roles for requirements, build, independent review, testing and release, under an overseer with a state document and human sign-off. Changed: Many projects in parallel, each supervised, each with an audit trail. Role: Designed and built.
    • Agent control room. A small local dashboard to supervise many AI agent projects at once: a map of every project lead (overseer) by area, the specialist agents under each, a “needs you” stack of decisions waiting on a person, and a console to read and message each one. A policy decides which agents may message which. It runs on the laptop and uses no AI itself. Changed: One person can oversee many parallel workstreams without losing track or becoming the message bus. Role: Designed and built.
